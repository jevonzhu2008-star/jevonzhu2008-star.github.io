Fabric 这周四条更新：接入变简单，治理更难

Fabric 四条更新全在拆边界：跨租户共享、私有链路、SQL 池统一。接入变简单了，治理反而更贵。

  • Fabric
  • Power BI
  • 数据治理
  • 企业架构

Fabric 这周四条更新，没有一条是给分析师看的。

没有新图表，没有新 DAX 函数，也没有 Copilot 的新按钮。四条分别是：跨租户共享数据的 IQ Share（预览）、Eventstream 自定义端点支持私有链路（预览）、SQL 池配置统一，以及微软连续第六年进 Gartner 数据集成魔力象限 Leader。

四条放在一起，方向一致：Fabric 在降低「把数据接进来」的成本。跨组织、跨网络、跨工作负载，三道边界各拆一道。

同一批素材里还有一篇不是微软写的。Prologika 的 Teo Lachev 在 10 月 23 日问了一句：业务逻辑到底该放哪一层。这篇跟前面四条没有直接关系，但它是前四条的反面——平台把接入做成默认，治理就变成了自选动作。

一、跨租户：共享的不只是数据，还有说明书

IQ Share 现在预览。可以把整个 Lakehouse、Warehouse 和 Mirrored Items 共享给另一个 Fabric 租户里的接收方。

技术上不新。跨租户走 shortcut，数据不复制，留在生产方租户里。对方那边新加的表，会自动出现。这些是管道，早就有。

新的地方有两处。一是上下文跟着数据走。Lakehouse 里可以放 markdown 文件，写业务定义、假设、使用说明。接收方配下游分析或 AI 时，能直接读。二是共享有了生命周期。接收、撤回、到期时间都有。所有共享关系可以在 OneLake Catalog 里集中看。API 和 CI/CD 也能创建和接受共享。

我的看法：这是把「共享」从一次性动作，变成一段有开始有结束的关系。

对企业之间很有用。给供应商共享库存湖仓，给客户交付带数据字典的仓库，跟外部顾问做限时的联合财务分析。这些场景原来靠导出、拷贝、对账。现在靠一条 shortcut 加一份说明书。

但说明书只是说明书。接收方看不看，系统不管。你写错了口径，也不会报错。跨租户之前，合规问题先摆到桌面上。数据出境、行业监管、对方租户的权限模型，这些不是预览功能能替你回答的。

跨租户解决的是组织边界。还有一道，是网络边界。

二、私有链路：内网应用不用再开公网口子

Eventstream 的自定义端点，现在支持 workspace 级的私有链路，预览。

场景很具体：有些应用跑在没有公网路由的网段里，比如工厂产线、金融机构的内网系统。它们要把实时事件发到 Fabric。以前只有两个选择——开个公网口子，或者干脆不接。

现在有第三个。这类应用本来就没有托管连接器可用。走自定义端点，用 Kafka、AMQP 客户端或者 Event Hubs SDK，把事件推到自己 workspace 的私有链路里。链路按 workspace 走。一个 workspace 映射到一个虚拟网络，有自己的 private link service。多个虚拟网络可以用各自的私有端点连进来。反过来，一个虚拟网络也能连多个 workspace。

我的看法：这条最像「给甲方 IT 看的更新」。

制造业、金融的内网系统，数据出不了网是常态。以前为了一条实时流，网络和安全要开三次会。现在网络架构不用动，应用侧改一下连接地址。FQDN 由 workspace ID 拼出来，在虚拟网络里解析成私有 IP。

代价在运维。私有链路是 workspace 级的。workspace 一多，private link service 和 private endpoint 的对应关系就得有人画图。预览阶段，先拿一条非关键链路试点，别一上来就挂生产。

网络通了，接下来是算力怎么分。

三、SQL 池统一：一条要看日期的更新

SQL 池是 Fabric Data Warehouse 自带的工作负载管理能力。以前分内置池和自定义池两套配置模型，现在统一成一套，UI 和 API 都走同一个配置。

这条更新没有新功能，只有日期和默认值。

第一个日期是 2026 年 12 月中。customSQLPoolsEnabled 这个标志停用。以前可以用它取已经失效的池配置。之后 GET API 只返回当前有效的配置，失效配置在 UI 和 API 里都不再出现。

第二个是 2027 年 1 月。新 workspace 默认用统一的单池配置。一个读优化的池，能访问 100% 的可用算力，服务所有工作负载。老 workspace 保持现有配置和行为，不需要迁移。官方文档会跟 1 月的发布一起更新。

真正要盯的是配额，而且只影响新 workspace。现在默认是 SELECT 和非 SELECT 各 50%。新默认下，两类都能用到 100%。查询可能更快，算力消耗也可能更高。新 workspace 默认打开 Optimize for Reads。跑大批量写入、又不太复用缓存的场景，要重新评估这个开关。

我的看法：这不是迁移，是默认值变更。

做了 10 年报表。功能下线没事、默认值一变就出事，这种事见过太多次。两类人要动。写 API 集成和自动化的，12 月中之前把 customSQLPoolsEnabled 的逻辑去掉，改成直接读池配置。管容量的，1 月以后新建 workspace 之前，先把预算重算一遍。从 50/50 到「谁先跑谁吃满」，隔离换成了弹性。吵闹邻居的问题，从平台回到了你的治理流程。

四、Gartner 六连冠：通稿要读它选择讲什么

微软连续第六年进 Gartner 数据集成工具魔力象限的 Leader。评估的两个维度是愿景完整性和执行能力。参评的工具包括 Fabric、Azure Data Factory、SSIS、Power Query 和 Azure Synapse Analytics。

这是通稿。结论不用看，六连冠说明不了你的项目会成功。

有用的是它反复强调的几件事：开放生态、实时数据、数据治理。开放这条最具体。Mirroring、OneLake shortcuts、对接 Apache Spark 和 Apache Airflow、跟 dbt 合作做原生转换。翻译过来就一句：不要求你把数据搬过来。

评级是给采购看的，架构判断还是得自己做。但它和前三条更新指向同一个方向，这一点值得记。

四条更新讲完了。有一件事它们都没回答：逻辑放哪。

五、反面：业务逻辑到底放哪一层

Prologika 的 Teo Lachev 在 10 月 23 日写了一篇短文。他正在做一个 Qlik 到 Power BI 的迁移，一个挺复杂的财务看板。每次觉得快做完了，又从 Qlik 里挖出一条业务规则：计算口径、维度表里的占位行、分摊覆盖。

于是他列了一张表。

能物化的，放 ETL 和星型模型表。数据质量问题、自定义分类、分摊、可以提前算好的计算，都归这里。

计算列优先放 ETL。原因有两个：业务逻辑集中在一处；Direct Lake 表对计算列支持有限，他的原文写的是不支持。

终端用户的调整，放语义模型。元数据、层次结构、显示文件夹、自定义排序，都算这一类。

度量值、RLS 和 OLS，也放语义模型。

纯展示的东西，比如某张报表用的字段参数，可以只放报表里。如果 Excel 这类客户端也要用，再挪回语义模型。

他的经验法则：能复用的业务逻辑，尽量往上游物化；依赖运行时上下文的，留在语义模型；只跟某个展示有关的，留在报表层。

我的看法：这张表比前面四条更新都值钱。

多数团队的默认不是这张表。默认是「能在 DAX 里写就在 DAX 里写」，因为快。快有代价：口径散在几十张报表里，换工具的时候要重新挖一遍。Teo 说的就是这个。过度依赖语义模型和 Power Query，逻辑会去中心化。哪天不用 Power BI 了，反推规则的成本高得离谱。

更关键的是顺序。边界拆得越多，这个问题越尖锐。数据可以零拷贝跨租户进来，内网应用可以直连进来，新 workspace 默认吃满算力。每一步都在降低「接进来」的成本，没有一步回答「这个数算在哪」。

四条更新和一篇反面

四条微软更新，三条讲接入，一条讲配额。接入的成本在降，治理的成本在升。

IQ Share 里的 markdown 是「说明」，Teo 的分层表是「约束」。说明可以忽略，约束不能。这一组素材里，只有一篇在讲约束，偏偏它不是微软写的。

SQL 池的变化也是同一个逻辑。50/50 是隔离，100/100 是弹性。弹性对跑批友好，对账单不友好。平台把选择权交回来，代价是你要自己定规则。

Gartner 把「开放」写进理由，说明微软的差异化不在功能多，而在接入少。接入越少，平台越像高速公路。高速公路不负责你车里的货对不对。

把时间线排一下：10 月 23 日 Prologika 问逻辑放哪，10 月 29 日私有链路，11 月 4 日 IQ Share，11 月 9 日 SQL 池和 Gartner。两周半，四条更新，一个方向。Fabric 正在从分析平台，变成企业之间的数据交换平台。交换越频繁，口径分叉的概率越高。

我的判断

必看：SQL 池统一。有硬日期，12 月中之前检查 API 集成，1 月以后重算新 workspace 的容量预算。这条优先级最高。

可选：Eventstream 私有链路。内网应用多、实时需求明确的团队可以试点。预览阶段别挂关键链路。

观望：IQ Share。功能方向对，但跨租户先过合规。预览阶段别当生产依赖。

不用看：Gartner 通稿。给采购看的，不是给你看的。

现在就做：把 Teo 的分层表抄下来，写进自己项目的建模规范。这件事不需要等任何版本，也不需要预览资格。

Fabric 在把接入做成默认，治理没有默认值。这一周真正该记的不是四条更新，是这句话。
